# J813 PMCCNTR assist dispatch — pre-code failure model

Base is clean Aura d40229b41ba84ab0da0cc13067d054f3de39d6a4, the currently qualified freeze02. Work is isolated; no live source, image, guard, registry, CPU frequency or firmware state is changed. Root owns all hardware activation. A future freeze changes source commit and therefore needs a new reviewed source-binding mechanism; the boot119 amendment is not silently reusable.

## Evidence and scope

Complete immutable121/122 logs show many indexed-HVC absent-register accesses. Encodings d53b9d08/d53b9d0b are MRS PMCCNTR_EL0 into x8/x11; d538cc09 is ICC_IAR1_EL1 into x9. The former uses hv_host_counter(), which returns the established scaled timer alias plus epoch offset; it is not a measured CPU-cycle or frequency source. GIC IAR reads acknowledge real emulated/carrier state and cannot be replaced by a timer read or cached value. The diagnostic counter is global, sampled and non-atomic; sampled instruction proportions and counters are not exact workload statistics.

The exact linked freeze02 ELF shows generic assist allocating0x150 stack bytes and calling memset for256 scratch bytes before dispatch. This is concrete avoidable work for the exact PMCCNTR read. It is not a measured speedup or memory-bandwidth bottleneck. **Do not remove generic zero initialization:** native-AIC GIC carrier diagnostics read regs[18] even when Rt differs.

Proposed sole production change: in hv_handle_t8142_sysreg_assist, recognize the exact MRS PMCCNTR_EL0 instruction (all32 Rt values), only for T8142 with apple_sysregs_unlocked false. Return the unchanged hv_host_counter() value through the existing optional output. Every other instruction uses the byte-identical generic implementation. The image-scan probe remains on that generic implementation. No hot-path log suppression, time scale, counter epoch, PMU policy, IRQ dispatch or guest code-patching policy changes.

## Failure cases identified before implementation

1. Wrong instruction direction, adjacent register/field, unknown instruction, non-T8142 chip, or unlocked Apple PMU must not take the new fast branch. Generic return value, output-preservation and side effects remain unchanged. Exercise bit perturbations and representative full PMU/GIC traffic.
2. Every destination x0–x30, including ABI-preserved x19–x28, receives the same value. XZR/Rt31 remains discarded by the existing caller. No other GPR, stack pointer, PSTATE, fault state or PC changes. Indexed sites keep ELR after the HVC; pending UNDEF unwinds to faultPC+4 and the saved pre-fault PSTATE. Relocated indexed sites still work; invalid index/immediate/compatibility refuses.
3. The exact existing timer alias scale, offset and fallback counter must be used. Test divide-by-three boundaries, large values, wrap arithmetic and nonzero offsets. A null output pointer still performs the same single counter read, without a write. No stale cached counter, raw24MHz value, guessed multiplier or new frequency claim.
4. PMCCNTR writes retain current software behavior; other PMU controls stay unchanged. Unknown fallback must preserve output sentinels. Probe mode must retain the original generic behavior and may never acknowledge an interrupt.
5. Interleaved PMU reads and GIC IAR/EOI traffic must retain the pending/active token and generic zeroed scratch (including regs[18]). The hardware/carrier boundary is modeled for this dispatch E2E, while the entire production GIC implementation is required byte-identical to base. A fast read must never call GIC or mutate its state.
6. All surrounding hv_exc_sync context publication, rendezvous, hv_update_fiq, native-AIC exception entry, vector repair, debug counters and diagnostic cadence stay byte-identical. Full1Hz housekeeping/WFI/EL1 observability and1ms wake deadlines remain frozen. No new early return around the architectural return path.
7. Compiler/LTO may retain the slow frame or bypass the intended branch despite source appearances. Bind native assembly to the actual built image and verify a dedicated PMCCNTR path reaches the same counter calculation without calling generic scratch initialization, while fallback still reaches the original generic function. Do not turn instruction counts into elapsed-time claims.
8. Wrong/dirty source, tool drift, missing local dependencies, changed capabilities or stale build artifacts refuse freezing. Offline build uses cached tools/dependencies only. Preserve failed attempts and original freeze02 rollback; no deployment until root review and authentic current-boot exit.

## Repeatable proof before deployment

Write the actual-source E2E before changing production. Compile verbatim clock/PMU/generic/public-wrapper/indexed-site/pending-UNDEF/trampoline functions, using real register encodings and modeled hardware registers, guest translation and GIC boundary. First run unchanged base for semantic proof and record its generic scratch path. Then repeat on the candidate, compare the full event trace to base and reject real source mutations (wrong mask/guard/counter/output/fallback/PC). Retain source/compiler hashes, generated C, sanitizer logs, traces and native ELF/disassembly. Existing1Hz deadline/report source is byte-checked against freeze02; no unrelated test suite is invented. Hardware performance and correctness remain separate root-controlled E2E work.
