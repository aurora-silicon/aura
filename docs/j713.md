# J713 (M4 MacBook Air) boot and firmware handoff

This series prepares J713 for the common Aurora boot flow: retained ANS
storage, PMU/SPMI resources, PCIe radio power and selected DART streams,
requested DAPF consumers, and the inherited display framebuffer. It is the
bootloader companion to the [basic Linux support](https://github.com/aurora-silicon/linux/pull/366).

Build stage 2 from `aurora-wip` plus this series:

```
make -j8 USE_CLANG=1 ARCH=aarch64-linux-gnu- RELEASE=1 CHAINLOADING=1 ESP_STAGE2=1
```

Append the J713 DTB and a gzip-compressed `u-boot-nodtb.bin` built with
`apple_m1_defconfig` from the companion U-Boot series. Preserve the ESP path
configured by stage 1; `/m1n1/boot.bin` is not necessarily the installed path.

ANS may already be running when stage 2 starts. Adopt that RTKit session
without replaying its handshake; initialize a stopped session when needed.
Admit the measured J713 split-BAR queue layout and publish validated live
ANS/SART/mailbox resources. Retain the session and its buffers for U-Boot.

PCIe endpoint power and stream IDs come from the DT. The J713 radio rail
uses the qualified native gP13 pKW4 action template 0x00800000 with argument
one. Unknown keys, namespaces or active-low wiring are refused. Optional
radio setup failure disables that controller while retaining the independent
ANS boot path. Disabling that controller does not undo a prepared rail,
link or DART state; those resources remain retained. Only selected unlocked
DART streams enter bypass; display translations are preserved. DAPF setup
needs both an explicit handoff request and a known active consumer.
T8132 additionally requires validated typed instance metadata: a selected
GAPF bank with no DAPF instance is preserved without filter writes. The
only genuine DAPF bank programmed is the AOP's, whose handoff kboot
qualifies: when the OS requests it and the AOP CPU is halted, kboot writes
the bank in register order, reads every slice back (restoring all of them
on a mismatch), and adds the AOP's DRAM firmware segments and DAPF windows
to its memory-region. Otherwise the AOP is disabled. Other genuine DAPF
selections are refused; this refusal does not remove independent,
explicitly requested consumer power.

The shared firmware handoff retains GPU and DCP reservations and validates
their metadata without starting native GPU or display drivers. Unknown
optional native resources leave the firmware framebuffer available. Keeping
these reservations is necessary even when the OS uses software rendering.
Native Linux GPU/DCP activation remains a separate kernel series.

U-Boot initializes and retains the MTP helper. Linux owns DockChannel
discovery and keyboard/trackpad configuration. Use the companion
[U-Boot review branch](https://github.com/aurora-silicon/u-boot/tree/m4/pr1-basic-bringup)
and matching Linux DT/UKI handoff support. Per-kernel DTBs are prepared through
EFI fixup without replacing the shared raw DTB bundle.

The stage-2 control DTB must provide `atcphy0` and `atcphy1` aliases for
banked T8132 USB3 calibration export. Bluetooth requires a `bluetooth0`
alias and the matching `pci14e4,5f72` endpoint node so the shared handoff
can publish the per-machine address and Taurus calibration. The AOP
handoff requires an enabled `apple,t8132-aop` node at the path the OS tree
uses for it (`/soc/aop@390600000`): its reservations are described for that
node, and U-Boot carries them to the per-kernel DTB's AOP by path. Without
the node, m1n1 leaves the AOP alone. Preserve a
USB2-only control topology when retaining older fallback kernels; the
per-kernel DTB selects which qualified port has USB3 resources. The
companion U-Boot importer copies calibration without adding OS topology
or importing the control DTB's power-ownership policy.

Qualification must record both running bootloader versions after a real
reboot, the kernel's imported DT provenance, and physical display/input
response. A successful build or host test does not establish hardware support.

## Padded Stage 1 layout

The padded Mach-O Stage 1 for J713 has the same layout from aura 1.0.0b9 to 1.0.0b12: kcrz
0x920c000, the same `__TEXT_EXEC` execute window and the same entry point (checked on a J713 by
a tester, 2026-11-13). A Stage 1 rebuilt from a newer aura in that range keeps the window
iBoot arms.
