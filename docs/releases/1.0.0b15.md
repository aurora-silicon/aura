# Aura 1.0.0b15

This release is for Macs that run the macOS 27.2 (26B123) startup firmware. Packaged in the distributions, it boots every M2, M3 and M4 Mac in our lab that runs 27.2: the Mac mini M2, the 15-inch M3 MacBook Air and the 13-inch M4 MacBook Air. 1.0.0b14.1 stopped in Stage 2 on every M2 on 27.2. It is cut from `main` and carries everything merged since 1.0.0b14.1.

## Booting on macOS 27.2

- **M2 (T8112): the boot no longer stops when the GPU firmware has no initdata layout (#381).** On 27.2 the M2's GPU firmware (`G14, G, 27, 2`) is one aura has no initdata layout for. 1.0.0b14.1 stopped at `Failed to prepare FDT` and dropped to the proxy, so these Macs never reached U-Boot. Now aura logs `GPU disabled, boot continues`, leaves the GPU node disabled and boots the OS. On the 26B123 stub, the Mac mini M2 (J473) boots Fedora with networking up.
- **M3 (T8122): the GPU is handed to Linux on 27.2 (#448).**
- **M4 (T8132): the GPU is handed to Linux on 27.2 (#379),** chosen by the GPU node and the firmware layout, not by board.
- **M4 internal display on 27.2 (#404):** the DCP's firmware clocks and display maps are published.
- **M3 MacBook Air external display (#437):** its external DCP is handed over by default where it runs the internal image. Its DART list is checked first, and aura refuses the handover when the list can't be read whole.
- **27.2 on the M3 Air DCP and the M1/M2/M3 ISP (#227).**
- **Firmware-27 DCP clocks from the ADT on the legacy display path (#382).**

## Other changes

- Every video encoder is handed over by its block, each matched to its ADT node by address, at its DART's window (#420). An encoder whose window or filter can't be checked is left off.
- One AOP firmware-segment path, chosen by the ADT and the DART's range (#377). A powered-down AOP DART's registers are no longer read, and firmware mappings on locked AOP DARTs are kept.
- The panel's `apple,max-brightness` is filled in from the ADT on dcp6 (#442).
- M4 Max (T6041): the v1 GPU calibration handoff, taken from the ADT and SGX (#450).
- T8152: the internal DCP's handoff state and its live AFK endpoints are published, and the display controllers are handed over powered off (#301, #419).
- The CLPC's Low Power mode ceiling is passed to the OS (#358). On T8142, the J704's 14/13 GPU perf states are accepted (#276).
- The `usb-drdN` controller defaults go to the dwc3 node on every ATC port that has them (#399).
- Post-M4 ANS warm start: stale messages are dropped first, and the IOP power report gets 6 s (#394).
- PCIe: each root port's DBI is set up at its own device, and a bridge whose device number isn't its port index is logged (#405, #423).
- Memory: L2 blocks over an armed CTRR range are mapped with L3 pages (#411).
- SPTM virtualisation: cpu-ids 32 to 34 stay in the S2R core masks and in the DCC transport's per-core state (#407).
- T6050: a bandwidth block under 4 bytes, or a framebuffer past `/vram`, now fails closed where the bounds checks used to wrap (#408).
- Build: a packager's `RUSTFLAGS` no longer reach the Stage 1 Rust build (#454). Fedora's `%build` flags (`-Copt-level=3 -Cforce-frame-pointers=yes`) had pushed Stage 1 past the DCP log buffer. Stage 1 is now byte-identical with or without them.
- Dead code, unused tools and duplicate CI builds were removed (#371), and a pre-PR checklist was added (#428). CI: maintenance tags are labelled as their source build (#431), and the alarm Stage 1 size job retries pacman (#434).

`VERSION` is `1.0.0b15`, so the tag build labels its images `1.0.0b15`.

## Known issues

- **No HDMI picture on the M2 Mac mini (J473) on 27.2.** aura doesn't light HDMI there (`dtpx-port is only supported with V13_5`); that is aura#451, which is not in this release. Linux then has only a 640x1136 placeholder framebuffer. The Mac boots, and the network and ssh work.
- **No external display on the 13-inch M4 MacBook Air (J713) on 27.2.** Its external display processors (dcpext0/1) are not handed over, and Linux logs `external display processor unusable (bind failed: -19)`. The handover is aura#440, which is not in this release. 1.0.0b14.1 doesn't have it either.
- **The M2's GPU stays disabled on 27.2.** Linux runs without GPU acceleration on an M2 on the 26B123 stub until aura has an initdata layout for that firmware.
- The 1.0.0b14.1 known issues on the MacBook Air M5 (T8142) still apply: no boot or trial watchdog (#414), and the `apcie,t8142` handoff line (#415).
